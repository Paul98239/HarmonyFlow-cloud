# 需要真人與真實攝影機的手動測試

雲端環境沒有攝影機也沒有真人，以下項目**沒有被驗證過**，需要你在實機操作。能用 Node 或無頭瀏覽器驗證的都已經寫成自動測試（`npm test`、`npm run test:e2e`），這裡只列自動測試做不到的部分。

每一項寫：要做什麼、要看什麼／聽什麼、怎樣算通過。開發者工具 console 的 `__stats()`、`copy(__pressLog())`、`copy(__visionLog())` 可以把當下的狀態與紀錄複製出來附在回報裡。

## 階段 0：合奏

### M0-1 PC 鍵盤手＋一位揮手的人
1. 選一首兩個以上聲部的歌，聲部 A 指派「PC 鍵盤手」、聲部 B 指派「演奏者 1」，現場人數選 1，開鏡頭。
2. 播放，兩個人一起演奏到一半，揮手的人走出鏡頭 5 秒再回來繼續揮。
3. 看／聽：揮手的人離開約 1 秒後，他的聲部由電腦（小聲）代打；回來揮的第一下接在合奏目前的位置，**不會多跳一個音**；伴奏不會擠成一團或突然停很久。
4. 通過：全程沒有卡住、伴奏沒有在兩人之間忽快忽慢地來回換。

### M0-2 兩人速度不同
1. 同上的指派，鍵盤手故意彈快、揮手的人照自己的速度慢慢揮。
2. 看／聽：伴奏跟著鍵盤手（帶頭的人）；揮手的人落後太多時直接接到合奏位置，而不是一個一個音慢慢補。
3. 通過：伴奏的速度不會每隔一兩秒就在兩人之間換來換去。

## 階段 1：演奏模式

### M1-1 三種模式的手感
1. 選一首有快音（十六分音符以上）的歌，聲部指派給 PC 鍵盤手，模式分別選「音樂家」「起音」「拍子」各彈一次。
2. 聽／感覺：
   - 起音：跟改版前一模一樣（每一下一個起音，太快的音自動補上）。
   - 音樂家：每一下都算，連按兩下就是兩個音；放開鍵音就停；速度跟著你忽快忽慢。
   - 拍子：一拍按一下，拍內的音（包括快音）由電腦照樂譜補；長音時多按的那幾下不會讓歌往前跑。
3. 通過：三種感覺分得出來，按下去當下就有聲音（拍子模式在你的聲部是後半拍進來時，按下去先聽到伴奏的拍子，你的音隨後進來）。

### M1-2 揮手的拍子模式
1. 演奏者 1 指派一個有快音的聲部、模式「拍子」，現場人數 1，開鏡頭。
2. 跟著音樂的拍子揮手，不管音符。
3. 通過：整個聲部（含快音）都奏得出來；揮得快時歌不會飆走（最多 1.6 倍速）。

### M1-3 自動切換
1. 模式「自動」，揮手的人故意只照穩定的拍子揮（不照音符節奏）約 10 下。
2. 看：狀態格出現「已改用拍子（照拍子在按）」；之後一下帶一拍。
3. 換一個人在「自動」下亂揮（越快越好）：切成拍子，歌不會越跑越快。
4. 固定選「起音」時同樣的揮法：不會切，只在狀態格寫「建議：拍子（…）」。

### M1-4 不同模式一起演奏
1. PC 鍵盤手「音樂家」、演奏者 1「拍子」，一起演奏一首歌。
2. 通過：伴奏跟著帶頭的人，沒有擠成一團或在兩人之間來回換。

## 階段 2：力度、音量與情緒

### M2-1 鍵盤的位置
1. PC 鍵盤手彈一段，只用左邊的鍵（A、S、D），再只用右邊的鍵（L、;、'）。
2. 通過：左邊明顯比較小聲、右邊比較大聲；空白鍵是原本的音量。音樂家模式差距更大。

### M2-2 揮手的力道與距離
1. 演奏者 1 先站在離鏡頭約 1.5 公尺揮，再走到約 3 公尺用同樣的動作揮。
2. 通過：音量差不多（不會因為站遠就變小聲）。
3. 換一位動作天生很小的人（或坐著、只動手腕）照他平常的方式揮一陣子，再試著比平常大一點：要聽得出變大聲，而不是一直都很小聲。

### M2-3 同一首歌、兩種表情
1. 同一首歌彈兩次：一次大而快地揮（手張開、揮得快），一次小而慢。
2. 看：人身邊的外接框，大而快時框大而亮、小而慢時小而淡。
3. 聽：兩次的整體音量與伴奏的熱度不同，速度也跟著動作；不會突然大小聲跳動。
4. 坐著揮一次：框照樣跟著動作變化（下半身不在畫面不影響）。

### M2-4 落拍與代打的音量
1. 兩人合奏，其中一位（不是帶頭的）故意慢半拍。
2. 聽：他的聲部漸漸變小聲（退到後面），而不是突然斷掉；他回到拍子上後漸漸恢復。
3. 他停手被代打時，代打的聲音比他自己彈時小聲，但仍聽得到、跟得上合奏。

## 階段 3：樂譜視覺化與骨架裝飾

### M3-1 看得懂「什麼時候要按」
1. 兩到三位演奏者（含 PC 鍵盤手）各指派一個聲部，其中一位用拍子模式，播放。
2. 看：每個人一條、顏色跟他的骨架一樣；自己的音從右邊流過來，亮的那幾個是「下一下會放出的」，大圓點碰到白線時按；拍子模式的圓點落在拍線上。
3. 故意停手：自己那條變橘色、圓點閃動、左邊寫「落後了」；再停久一點變紅、寫「電腦代打・按一下接回」；按一下接回來。
4. 通過：不用解說，長輩看得出輪到自己了沒有。

### M3-1b 黑幕上的版面
1. 一到四個人、加上 PC 鍵盤手，播放。
2. 看：骨架整個在頂端工具列與樂譜面板之間，揮到最低時手也不會被面板蓋住；ID 標籤不被工具列切掉、人多時不互相疊；每一條樂譜在黑底上分得出來。
3. 人站遠或人多時骨架會比較小，請回報實際的大小是否還看得清楚（可以再調面板的高度上限）。

### M3-2 骨架裝飾
1. 一位演奏者大動作揮、一位小動作揮。
2. 看：揮中的那一刻手會閃一圈；大動作的人光暈、外框比較大比較亮；不會閃爍、不會卡頓。

### M3-3 主執行緒負擔（在你的機器上）
1. 現場人數 4（或實際人數），播放 30 秒，在 console 執行 `__latency()`、`__skeletonStats()`、`__scoreViewStats()`。
2. 通過：`主執行緒佔比%` 跟改版前差不多（雲端量到 +0.6 個百分點）；`排程tick間隔ms` 的 `超過50ms` 次數沒有變多；按鍵到出聲沒有變慢（`__stats()` 的 `估計按下到出聲ms`）。

## 階段 4：上場防呆

### M4-1 亂序操作
1. 不照順序操作：先指派再選歌、先播放再開鏡頭、播放中改現場人數、播放中改指派與模式、試聽後再演奏、重置 ID 後再揮手。
2. 通過：任何時候都不會出現「播放、暫停都不能按」的狀態；最後都能演奏。

### M4-2 面向鏡頭
1. 現場人數 1，指派一個聲部給演奏者 1，人先背對鏡頭（或站在畫面外）。
2. 看：舞台中央出現「演奏者 1 還沒出現在鏡頭裡：請面向鏡頭…」；播放後他那一條寫「看不到你・請面向鏡頭」。
3. 轉身面向鏡頭：骨架出現、提示消失，揮兩下就能演奏。
4. 演奏中走出畫面再回來：回來時一樣要看得到臉才會被找到，提示會再出現一次。

### M4-3 多人靠近
1. 兩到四個人站一排演奏，中途兩個人靠在一起（肩碰肩）、手臂交叉、其中一人從另一人前面走過。
2. 通過：骨架不會跳到另一個人身上，ID（頭上的數字與顏色）不會交換；A 揮手不會讓 B 的聲部出聲。
3. 兩個人一起走出畫面、換位置回來：各自拿回自己原本的 ID。
4. 有問題時：當下按 ❚❚，在 console 執行 `copy(__visionLog(15))` 把最後 15 秒的逐幀紀錄附上。

### M4-4 幽靈 ID
1. 現場人數選 3，只有 1 個人在鏡頭前。
2. 看：指派下拉裡演奏者 2、3 標成「（未偵測到）」。
3. 把一個聲部指派給演奏者 3、另一個給演奏者 1，播放：演奏者 1 照常演奏，演奏者 3 的聲部由電腦小聲代打，不會整首卡住。

### M4-5 突發狀況（真的裝置）
1. 演奏中拔掉耳機（或切換藍牙耳機、讓手機來電）：演奏先暫停，頂端寫「聲音被系統暫停了…」；按 ▶ 從原處繼續、有聲音。
2. 演奏中切到別的分頁或縮小視窗再回來：演奏已經暫停，頂端寫「切到別的畫面時演奏已先暫停…」；按 ▶ 繼續。試聽時切走不暫停。
3. 演奏中按住一個鍵不放、同時 Alt+Tab 切走：回來時那顆音沒有卡著響。
4. 有怪事時在 console 執行 `copy(__faults())`，把錯誤紀錄附上（自動化測試只能模擬 1、2，真的耳機與來電要人測）。

## 背景樂器與溫暖風格

### M7-1 背景樂器跟著聲音（真的裝置、真的聲音）
1. 選一首有鋼琴、鼓、弦樂的歌，五個聲部分給鍵盤手與四位演奏者，播放。
2. 看：每個人身後各有一件樂器（鍵盤手的在旁邊空著的地方）；人走動時樂器跟著滑過去。
3. 鋼琴：按下去時亮的琴鍵就是你聽到的那幾個音（高音在右）；鼓：聽到大鼓時是中間的大鼓在跳、聽到鈸時是上面的鈸亮。
4. 通過：畫面跟聲音同時（看不出先後），沒有人彈時樂器靜止，電腦代打時樂器變淡但還在動。
5. 長時間（10 分鐘）演奏時用 `__instrumentStats()` 看每幀耗時（平均應 < 1ms）。

### M7-2 溫暖風格
1. 在電視／投影機上看：底色是深暖棕（不是純黑也不刺眼），工具列、時間條、歌名、狀態格都清楚。
2. 長輩站在兩三公尺外：時間「0:42 / 3:15」、狀態格的字讀得到。
