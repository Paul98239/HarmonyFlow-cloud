# 決策紀錄

開發時遇到需要判斷的地方，都選「最容易回頭」的做法先繼續，記在這裡：決定、理由、替代方案。編號依時間排。

## 共通

### D0-1 測試只用 Node 內建，不加套件
- 決定：單元與模擬測試用 `node --test`（`npm test`），端到端用環境裡預裝的 Playwright（`require('playwright')`）與 Node 內建 http 伺服器（`npm run test:e2e`）。`package.json` 只有 scripts，沒有 dependencies。
- 理由：app 本身沒有建置流程與相依；測試工具也不該讓部署多一個步驟。
- 替代：Vitest／Jest（要 npm install）。之後需要覆蓋率報表再考慮。

### D0-2 測資是程式產生的合成樂譜
- 決定：`test/helpers/songs.js` 用固定種子產生 12 首結構各異的 MIDI（快音群、弱起、不規則小節、未量化錄製、SMPTE、卡農與長休止、四聲部、鋼琴和弦與踏板、鼓、慢板長音、單聲部），測試一律掃整個測資庫，不針對某一首調參數。合奏測試另外在每首後面加一個「在每兩個起音正中間放一顆音」的伴奏聲部（只有兩個聲部的歌兩個都被指派時本來沒有伴奏，量不出伴奏的問題）。
- 理由：規則要對任何 MIDI 成立；真實曲目有版權疑慮，也不知道哪些結構被涵蓋。
- 替代：之後可以把使用者的曲庫匯出幾首放進 `test/fixtures/`（要確認授權）。

### D0-3 「單人、現有模式手感不變」用逐筆基準比對
- 決定：`test/fixtures/onset-single-baseline.json.gz` 是用**原本的 commit（e8c1553）**的排程器跑出來的：12 首 × 前兩個聲部 × 鍵盤／揮手 × 三種速度（含偶爾連按）共 138 段，記下每一次合成器呼叫的時刻、音高、時間戳。`test/baseline.test.mjs` 用目前的程式重跑並逐筆比對。**力度不比**（階段 2 刻意依按鍵位置與揮手改變力度）。
- 理由：「手感」最可靠的定義就是「每個音什麼時候響」；比對逐筆時刻比任何統計都嚴。
- 替代：只比統計（平均延遲等），抓不到個別音的改變。
- 重新產生的方法：`git worktree add /tmp/base e8c1553 && node test/tools/gen-baseline.mjs /tmp/base/src test/fixtures/onset-single-baseline.json.gz`。

## 階段 0：合奏檢查

模擬方法：`test/helpers/sim.js` 用假合成器記下每一次呼叫、12ms 一次 tick（同 `midiPlayer.js`），演奏者用「機器人」：照排程器自己公布的下一個要按的起音、照自己的速度從自己上一下接著數（被合奏拉走之後從新位置繼續），可加速度倍率、手抖、漏按、多按、停手再回來。檢查項目（`test/helpers/metrics.js`）：放行卻不是當下發聲、伴奏擠成一團、伴奏比帶頭的人晚、帶頭的人來回跳、同一顆音發聲兩次、卡音、代打交還多推一格。

找到並修掉的問題（這些測試在原本的程式上會失敗，修完通過）：

### D0-4 落後跳到聲部結尾時回報「放行」卻沒有聲音
- 現象：不是帶頭的人落後太多，按下時合奏已經走過他最後一個音，落後跳把剩下的音都跳過，`trigger()` 卻回傳 true、按鍵記錄是 `released`。
- 決定：這種情況記成新的結果 `late`、回傳 false（他的聲部已經結束）。**不補放走過的音**：會在錯的位置響。
- 替代：補放最後一個音當回饋。放棄理由：跟合奏對不上，而且「不加檔案裡沒有的音」之外，也不該在錯的時間放原檔的音。

### D0-5 兩個不穩的人在一兩秒內來回交棒
- 現象：帶頭的人停住 → 交給第二位 → 第二位一秒後也停住 → 換回第一位（漏按、手抖多的兩個人時常見）。伴奏在兩人之間跳。
- 決定：新增「最短帶頭時間」`ENSEMBLE.LEADER_TENURE`＝max(2 拍, 1.2 秒)：換上來的帶頭者在這段時間內不會因為停住（overdue）、多數決被換掉，名單更前面的人恢復後拿回帶頭（return）也要等現任帶滿。離開鏡頭（absent）不受限。
- 代價：新帶頭者真的停住時，伴奏最多多等約 1.2 秒。
- 替代：加大第一段寬限。放棄理由：會讓所有換人都變慢，連第一次換人也是。

### D0-6 剛「落後跳」過的人馬上被交棒
- 現象：晚進場的人第一下就落後跳到合奏位置，這時帶頭的人剛好出狀況，帶頭交給他；他的位置是合奏給的不是自己的節奏，0.4 秒後又出狀況換回來。
- 決定：落後跳過的人要連續 `ENSEMBLE.JUMP_RECOVER_PRESSES`（2）下同步（同步／稍快稍慢）才有資格接手帶頭；現任已經不能帶（沒有人、停住且不算正在彈、被代打、彈完）時例外，免得沒人帶。
- 替代：跳完直接讓他帶、但把合奏錨點拉回他之前的位置。放棄理由：合奏會倒退。

### D0-7 跳位置的目標 tick 浮點誤差
- 現象：換帶頭者跳位置時目標是 `9599.999999…` 而不是 `9600`，結尾剛好在 9600 的音被當成「還在響」追音，發出一個 0 長度的音。
- 決定：跳位置的目標（換帶頭、落後跳、進入代打）離整數 tick 不到 1e-6 就當成那個整數（`snapTick`）。

### D0-8 換帶頭跳位置不算「伴奏擠成一團」
- 換到一個比合奏超前的人時，合奏照規則跳到他的位置（垂直切片：中間還該響的追音、整顆在身後的跳過），他的音與伴奏同一刻響。跳點前後兩個音靠得近是這條規則的結果，量「擠成一團」時排除換帶頭那一刻起 60ms 內的音。
- 替代：合奏用加速追上去（不跳）。放棄理由：新帶頭者按下去的音跟伴奏會有一段對不上，違反「觸發那一下當下跟合奏一起響」。

檢查過、沒有問題的：代打交還（77 種「回來的時刻 × 歌」，回來的第一下一律放出電腦還沒放的第一個起音或接手剛放的那一下，沒有一次多推一格）、離開鏡頭一秒代打、暫停續播、播放中互換聲部、主執行緒每 0.7 秒卡 80ms。

### D0-9（階段 1 時發現）代打重建佇列時重複排了已送出的音
- 現象：合奏重新對時（換帶頭、拍子模式開始一拍）會重建被代打的人的佇列（`_substituteFrom`），lookahead 已經帶時間戳送出、自動放行還沒到的那顆音被再排一次，響兩次。原本的程式在換帶頭時也走這條路。
- 決定：重建時跳過已經發聲過的音。混合模式的掃描測試（`test/modes.test.mjs`）抓到的。

## 階段 1：演奏模式

### D1-1 三層的定義
- **起音（onset）**：原本的行為，一行都沒改（逐筆基準測試保證）。
- **音樂家（musician）**：分組跟起音一樣（只併真的按不及的近距起音），差別是「他按的每一下都算」：去抖只擋 50ms 內的機械彈跳、估速視窗 3 個間隔（速度跟著 rubato 走）、揮手超前不鎖（可以帶到前面）、鍵盤的音長由放開決定、力度完全由按法決定（階段 2）。
- **拍子（beat）**：一下帶一拍。拍子單位（`src/midi/beats.js`）＝同一拍裡他的所有起音，拍內的音照樂譜依他的速度由電腦補上（沿用起音模式「組內自動放行」的機制）；不揮，這一拍就不會開始。音長照樂譜（不看放開）。
- 「音值」我解讀成力度（長短已經另外列了）；如果你指的是時值，請告訴我。

### D1-2 拍線從哪裡來
- 檔案有四分音符、而且音符真的落在拍號格線上（有音的拍裡 ≥ 45% 拍線上有起音）：用拍號格線（複拍子照 cc 換算）。一拍短於 0.36 秒就在小節內兩兩／三三合併（5/8＝2+3、7/8＝2+2+3），長於 1.25 秒就均分（不能一下自動放太久）。
- 否則（SMPTE 沒有四分音符、未量化錄製、速度表跟演奏對不上）：從全曲起音估脈動（起音兩兩的間隔落在週期整數倍附近的程度，偏好 100 BPM 一帶），再沿著起音一拍一拍找（找到起音就落在上面，找不到照週期推，週期只在 0.75～1.33 倍間微調，跟得上 rubato）。
- 弱起不用特別處理：格線從 tick 0 起算，弱起的音落在它真正的那一拍；脈動從第一個起音起算。
- 測資驗證：未量化錄製（真實拍長 0.79 秒±15%）估到中位數 0.76 秒；所有測資的拍線間隔都 ≤ 1.25 秒。
- 替代：Ellis 2007 的動態規劃拍點追蹤。比較準，但程式多一倍；目前的貪婪法在測資上夠用，之後可以換（介面只有 `beatLines(score)`）。

### D1-3 拍子模式的單位頭一定是他自己的音；切分拍「開始這一拍」
- 他這一拍的第一個音就在拍線上：按下去當下響（0ms），跟起音模式一樣。
- 他這一拍的第一個音在拍線之後（切分）：這一下是「開始這一拍」——他帶頭時合奏此刻走到拍線，拍上的音（通常是低音、和聲）當下響，他自己的音照樂譜在拍內出來（預按 `beat`）。這跟休止符鎖同一類：他自己的聲部在拍線上是空的。
- 替代：按下去就放他的切分音（提早半拍）。試過，會把切分拉到正拍、合奏跟著被拖動，測試量到伴奏擠成一團，放棄。

### D1-4 拍子模式的「打拍子」
- 跟著拍子揮的人每一拍都會揮，包括自己的長音還在響的拍。離下一拍的拍線還超過 0.6 拍的那一下記成 `hold`：不加音、不往前，但算他正在彈、而且**進估速**（拍線到拍線）——只用放音的那幾下估速，長音多的聲部速度會越估越慢、合奏越來越拖（測試裡實際發生過）。
- 去抖從「上一下被接受的按鍵」算，另有下限＝這一拍在速度上限（1.6 倍）下的長度的 0.9 倍：亂按最快也只到 1.6 倍。

### D1-5 「一揮跑出好幾個音」
- 起音模式的分組（揮手 0.3 秒內按不及的起音併成一下）是原本的設計，單人手感不能變，所以不改。解法是讓它**看得到**：`scheduler.viewState()` 公布「下一下會放出哪些音」（狀態列與階段 3 的樂譜都畫它）；拍子模式的預告跟實際 100% 一致，起音模式依按下那一刻的速度分組，偶爾差一個（測試要求 ≥ 95%）。
- 想要一下只出一個音的人用音樂家模式（只併真的按不及的），想要一下一拍的人用拍子模式。

### D1-6 快音群
- 三種模式都靠「組內自動放行」：按不及（依目前速度換成真實時間、比這個輸入來源連按的極限還近）的起音照樂譜時刻由電腦放，不管是十六分、三十二分、六十四分顫音、五連音還是 10 tick 的倚音——判斷是真實時間，不看音符種類。
- 拍子模式：拍內所有音都由電腦補上。測試：只跟著拍子揮，12 首 × 2 個聲部 × 鍵盤／揮手 × 三種速度，每個音都響了。

### D1-7 智能切換（`src/midi/modeAdvisor.js`）
- 預設「自動」（從起音開始）。選了固定的模式就不切、只在狀態列給建議。
- 自動只往容易切（亂按、跟不上、只照穩定拍子按 → 拍子；拍子模式卻在照每個音按 → 起音），不會自動升到音樂家（只建議）：音樂家幾乎不擋連按，對不熟的人太容易出錯，這一步留給人決定。
- 切換在按鍵之間生效，切完至少 8 下、6 秒內不再切，不會來回跳。
- 訊號都只跟這首曲子自己的節奏比（按鍵間隔的平均度 vs 放出來的樂譜間隔的平均度、被去抖擋掉的比例、速度被推到檔案的幾倍、落後跳的次數），不看曲名、不靠固定 BPM。
- 主控權：模式怎麼切都不會讓電腦替他放下一拍；只有跟不上好幾拍（第二段防呆）才由電腦小聲代打，他再按一下就接回來。

### D1-8 跟不上：先提示、再小聲介入
- 狀態（`viewState().performers[].state`）：落後一下（錯過一個起音、或落後偏離／脫隊、或停住超過寬限）就是 `behind`，狀態列顯示「落後了，跟著亮點再來一下」；仍跟不上（原本的第二段防呆：錯過 4 下而且離上一下 4 拍以上）才代打，代打的音是原檔力度 × 0.6。
- 替代：一落後就小聲代打。放棄：太快搶走主控權。

### D1-9 拍子模式的速度上限 1.6 倍
- 不懂音樂的人亂揮時歌不會飆走；想彈更快的人用起音或音樂家模式。

### D1-10 已知限制：提早按時 lookahead 已送出的那一顆
- 帶頭的人比合奏預期早按（拍子模式常見：照拍線揮），已經帶時間戳送出（最多 50ms 前）的那一顆伴奏音取消不了（worklet 沒有取消已送出事件的方法），會緊跟在新一拍的音後面響，形成兩個音的倚音般重疊（≤ 50ms）。原本的程式提早按時就有這個現象。測試的「擠成一團」改成量三個以上起音被壓在一起，兩個音的這種情況不算。
- 替代：縮短 lookahead。代價是主執行緒卡住時電腦音會遲到（原本 50ms 就是照實機量到的停頓訂的），不改。
